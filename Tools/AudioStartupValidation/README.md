# 오디오 시작 회귀 검증

Unity 2022.3.62f3의 별도 배치 편집기에서 실제 `SettingsManager`, `SoundManager` 및 두 오디오 정의 스크립트를 복사해 실행한다. 현재 열려 있는 프로젝트의 씬을 바꾸지 않는다. 임시 프로젝트와 결과는 `Temp/AudioStartupValidation/After`에 생성된다.

```powershell
& ./Tools/AudioStartupValidation/run.ps1
```

Unity 설치 위치가 다르면 `-UnityPath`를 지정한다. 제한된 실행 환경에서는 Unity 라이선스 IPC 접근 권한이 필요할 수 있다. 종료 코드 0은 성공이다. `results.txt`와 `Editor.log`에 자세한 결과가 남는다.

검증할 설정은 저장값 (마스터 0.37/BGM 0.23/SFX 0.17), 전부 0, 저장값 없음의 세 경우다. 각 경우 새로운 Play Mode를 시작하고, 설정 UI가 닫힌 로비 구조에서 게임 구조로 씬을 전환한다. 씬 `Awake` 전 설정 적용, `Start` 전 BGM 음량, 첫 BGM 선택과 음량, SFX 설정 준비, 설정 열기, 중복 매니저 제거, 슬라이더 동작, 포커스 음소거와 복원, 파괴 후 재생성을 확인한다.

저장 API는 메모리 값으로 대체하며 저장 시도는 예외로 처리한다. 게임 매니저, 이펙트 컨트롤러, 무기 기반 타입도 최소한의 대체 구현을 쓴다. 배치 테스트에서 화면 해상도 변경을 생략한다. 실제 저장 파일, 실제 게임 씬, 청취 결과, 배포 빌드를 검증하는 테스트는 아니다.

2026-10-13 결과:

| 코드 | 통과 | 실패 |
| --- | ---: | ---: |
| 수정 전 원본 | 53 | 13 |
| 수정 후 | 66 | 0 |

수정 전에는 로비에서 설정 매니저가 없고 마스터/BGM/SFX 값이 준비되지 않으며, 설정 UI를 열어 매니저를 만든 뒤에야 저장 음량이 적용되는 현상을 재현했다. 원본 비교는 수정 전에 보관한 `Temp/AudioStartupValidation/Baseline` 스크립트로 `run.ps1 -Baseline`을 실행했다. 이 임시 스냅샷이 없으면 해당 비교 옵션은 사용할 수 없다.

별도 프로젝트 C# 컴파일도 수정 전후 오류 0개였다. 게임 프로젝트 전체 `Assembly-CSharp.csproj` 컴파일은 수정 전후 오류 0개, 기존 경고 2개였다. 실제 저장 파일과 게임 화면의 최종 확인은 다음과 같다.

1. 로비 설정에서 마스터와 BGM을 0으로 설정하고 설정 창을 닫아 저장한다.
2. 게임을 완전히 종료한 뒤 다시 로비에서 시작한다. 설정 창을 열기 전부터 소리가 없어야 한다.
3. 마스터/BGM/SFX에 서로 다른 값으로 설정하고 저장한 뒤 재실행한다. 설정 창을 열어도 음량이 갑자기 바뀌지 않아야 한다.
4. 게임에 진입한 뒤 음량이 유지되는지 확인한다.
