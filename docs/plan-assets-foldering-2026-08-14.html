Assets 폴더링 상세 계획
리팩터는 후순위 · 이동만 먼저

Assets/ 전체를 대상으로, 같은 콘텐츠는 Scripts / Prefabs / Data에서 같은 도메인 이름으로 찾히게 정리한다. 코드·namespace·로직 변경은 하지 않고, 폴더/파일 이동 + .meta(GUID) 보존만 한다.

1 한눈에 보기

하는 것

  • Scripts / Prefabs / Scenes 폴더 정리
  • 빈 폴더 삭제
  • 해킹·UI·Audio 경로 통일
  • temp 씬 아카이브
  • 작은 PR로 Phase별 진행

안 하는 것 (1차)

  • namespace / 클래스 리팩터
  • Managers 책임 분리(코드)
  • 공백 폴더명 일괄 리네임
  • Resources → Art 대이동
  • Data CSV 경로 대규모 변경
한 줄 전략
도메인 이름 통일 + Unity 안전 이동(.meta 동반) + Phase당 1 PR. Scripts → Prefabs → Scenes 순. Data/Resources는 건드리지 않거나 최소만.

2 “같은 도메인 언어”란?

도메인 = 게임 안의 구역 이름 (Characters, Hacking, UI, Audio …).
같은 언어 = Scripts / Prefabs / Data에서 그 이름을 최대한 똑같이 쓰자는 규칙.

코드 리팩터(클래스 쪼개기)와 다름. 이름·위치 규칙에 가깝다.

이미 잘 맞는 예

의미ScriptsPrefabsData
캐릭터 Scripts/Characters Prefabs/Characters Data/Characters
무기 데이터/프리팹 .../Weapon 등 Prefabs/Objects/Weapons Data/Objects/Weapons

지금 어긋난 예 (고칠 대상)

의미ScriptsPrefabs / 기타문제
해킹 Scripts/Hacking (최상위) Prefabs/Objects/Hacking Objects 같은 기능인데 계층이 다름
무기 선택 UI Scripts/WeaponChoice (따로) Prefabs는 UI/Ingame UI인데 Scripts만 별도 루트
사운드 Managers/*Sound* Data는 Data/Sounds Managers에 섞여 있음
정리하면
“해킹이면 Hacking에 있다”가 Scripts든 Prefabs든 같게 읽히게 만드는 것.

3 원칙 · 안전수칙

강제 원칙

  • GUID 보존 — 파일과 .meta를 항상 같이 이동
  • 폴더링 ≠ 리팩터 — 스크립트 내용/namespace 변경 금지
  • 미러링 — 가능하면 Scripts ↔ Prefabs 같은 도메인명
  • 작은 PR — Phase 하나 = PR 하나
  • 서드파티 금지 — Plugins / TMP / ParrelSync / vFavorites

이동 방법

  • Unity 에디터 안 Move 권장
  • 또는 Unity MCP manage_asset
  • git만 쓸 경우 meta 포함 필수
  • Explorer에서 meta 빼고 옮기기 금지
  • 이동 후 Missing Script / Prefab 스모크
Windows 주의
tiles → Tiles 같은 대소문자만 바꾸는 리네임은 Git/Windows에서 깨지기 쉽다. 1차 폴더링에서는 하지 않는다.

Phase D — Scenes (+ Data 점검)

씬 아카이브 Data는 최소

Scenes

씬조치비고
LobbyScene.unity유지Build enabled
MainScene.unity유지Build enabled
LobbyScene temp, LobbyScene_TEMPPPPP, MainScene_TempScenes/_Archive/temp
JmgScene, Trick2Scene아카이브 또는 유지(팀 결정)Build disabled

Build Settings에 없는 경로(lhsScene, multiScene) 엔트리 정리. MainScene_Temp는 disabled로 등록되어 있으므로 아카이브 시 EditorBuildSettings.asset도 함께 수정.

Data

대규모 Data 이동 비추천 (1차)
BalancingSheetCatalog에 CSV 경로가 하드코딩되어 있음 (예: Assets/Data/Balancing/Objects/Map Objects/Map 1/...). Data를 옮기면 코드 수정이 필요 → 리팩터 경계. 1차는 점검만 하거나, 코드 수정 없는 초소형 정렬만.

AC

  • 활성 빌드 씬 = Lobby + Main (의도대로)
  • temp 씬이 _Archive에 있음
  • 데이터 로드/밸런싱 시트 경로 스모크 (이동 없었다면 회귀만)

Phase E — Resources → Art (후순위)

고위험 1차 제외

~7555 파일. Resources.Load 경로가 깨질 수 있음. 별도 승인·별도 기획.

현재 확인된 Load 예:

  • Characters/HackerData, Characters/CyborgData
  • Fonts/Maplestory Light SDF
  • Sprites/UI/SPR_MENU UI

사용처 전수 grep → 미사용분만 Art로 → 사용분은 Addressables/경로 수정과 함께.

Phase F — 리팩터 후순위

폴더링 아님
  • 공백 폴더명 → PascalCase
  • namespace를 경로에 맞게 통일
  • Managers 코드 수준 책임 분리
  • asmdef 도입 검토
  • 파일명 trailing space / 깨진 이름 정리
