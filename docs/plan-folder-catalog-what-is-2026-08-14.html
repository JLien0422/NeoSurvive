1 큰 폴더들이 뭐 하는 곳?

분류 전에, Assets 안의 “동네”부터 이해합니다.

동네Assets/Scripts/
뭐하는 것?
게임 로직 C# 코드가 모여 있는 곳. 플레이어, 적, UI, 매니저, 해킹 등.
분류
일부 이동 빈 폴더 삭제 대부분 유지
동네Assets/Prefabs/
뭐하는 것?
미리 조립해 둔 게임 오브젝트 틀. 적 프리팹, 무기, UI 패널, 해킹 장치 등. 씬에 꺼내 쓰거나 런타임에 스폰.
분류
해킹만 이동 예정 나머지 유지
동네Assets/Data/
뭐하는 것?
숫자·설정 데이터. CSV 밸런스 표, 캐릭터 ScriptableObject, 무기 스탯, 특성(Trait) JSON, 사운드 이벤트 정의 등.
분류
1차 유지 (경로를 코드가 직접 알고 있어서 함부로 안 옮김)
동네Assets/Resources/
뭐하는 것?
코드에서 이름(경로 문자열)으로 불러오는 에셋을 두는 특수 폴더. 스프라이트, 폰트, 사운드, 애니, 타일맵 등. 여기 넣으면 빌드에 잘 포함되지만 남용하면 무거워짐.
분류
구조 유지 안 쓰는 archive는 보류
동네Assets/Scenes/
뭐하는 것?
게임 화면 단위(씬). 로비, 인게임 메인 등.
분류
Lobby/Main 유지 temp는 아카이브
동네Assets/Plugins/
뭐하는 것?
외부에서 가져온 플러그인/미들웨어. 저장, 트윈 연출, 인스펙터 강화, 셰이더 등.
분류
본체 유지 예제만 삭제 후보
동네Packages/ (프로젝트 루트)
뭐하는 것?
Unity Package Manager가 관리하는 공식/원격 패키지 목록 (manifest.json). URP, TMP, 분석 SDK, MCP 등.
분류
필수 유지 애매한 건 보류
동네Assets/Settings/
뭐하는 것?
URP(렌더 파이프라인) 설정 에셋. 화면이 어떻게 그려질지 정하는 프로젝트 설정.
분류
유지
동네Assets/TextMesh Pro/
뭐하는 것?
유니티 글자(텍스트) 시스템 TMP의 리소스·폰트·설정. UI 글씨 표시에 필요.
분류
본체 유지 Examples만 삭제 후보

2 삭제 대상 — 뭐 하는 것들이길래?

삭제Scripts/Items/
뭐하는 것?
원래 아이템 시스템 스크립트를 넣을 자리로 만든 폴더로 보임. (드랍/골드/칩 등과 별개로 “아이템” 코드를 모으려던 자리)
지금 상태
파일이 하나도 없음. 빈 상자.
왜 삭제?
빈 폴더는 “여기 뭔가 있을 것 같음”만 주고 실제로는 검색·온보딩을 방해함.
삭제Scripts/Hacking/ObjectManager/ , Reward/
뭐하는 것?
해킹 기능의 하위 구역으로 예약된 자리. ObjectManager = 해킹 오브젝트들을 관리하는 코드 자리, Reward = 해킹 성공 보상 관련 코드 자리로 보임.
지금 상태
둘 다 비어 있음. 실제 해킹 로직은 HackingSystem, Effects, MiniGame 등에 있음.
왜 삭제?
쓸 내용 없는 예약 폴더. 나중에 필요하면 다시 만들면 됨.
삭제(조건부)Scripts/.../Weapon/Passive/
뭐하는 것?
패시브 무기(항상 발동/보유형) 스크립트를 넣으려고 만든 자리. Active(능동 무기)는 Cyborg/Hacker 아래로 이미 있음.
지금 상태
비어 있음.
왜 삭제?
앞으로 패시브 무기를 이 폴더에 안 넣을 거면 삭제. 넣을 계획이면 유지.
삭제Prefabs/Managers/
뭐하는 것?
매니저 전용 프리팹(예: DontDestroyOnLoad용 GameManager 오브젝트 틀)을 두려던 자리.
지금 상태
비어 있음. 매니저는 씬에 직접 붙어 있거나 다른 방식으로 존재.
왜 삭제?
빈 폴더 정리.
삭제Assets/Packages/
뭐하는 것?
이름만 보면 패키지 같지만, 진짜 패키지 목록은 프로젝트 루트 Packages/에 있음. Assets 안 Packages는 보통 쓰이지 않거나 실수로 생긴 빈 자리.
지금 상태
비어 있음.
왜 삭제?
주니어가 “패키지가 두 군데?”라고 헷갈림.
삭제 추천TextMesh Pro/Examples & Extras/
뭐하는 것?
TMP(텍스트) 패키지가 넣어 준 튜토리얼·데모 씬, 샘플 스크립트, 예제용 텍스처. “TMP로 글자 애니메이션 이렇게 한다” 같은 학습용.
우리 게임에서?
로비/인게임 UI는 우리 Scripts/UI와 Prefabs/UI를 씀. 이 Examples는 게임이 아님.
왜 삭제?
용량·검색 노이즈. TMP 본체(Resources/Fonts 설정 등)는 그대로 둠.
삭제 추천SerializableDictionary/Example/
뭐하는 것?
SerializableDictionary는 인스펙터에서 보이기 쉬운 직렬화 가능한 Dictionary 유틸 라이브러리. Example은 그 사용법을 보여 주는 예제 씬/스크립트.
왜 삭제?
예제만 지움. 라이브러리 본체(SerializableDictionary.cs 등)는 유지.
삭제 추천Plugins/Demigiant/DOTweenPro Examples/
뭐하는 것?
DOTween = UI/오브젝트 움직임·페이드 같은 연출을 코드로 부드럽게 만드는 트윈 라이브러리. Examples = 제작사가 넣은 데모.
우리 게임에서?
GameClearUI, GameOverUI 등에서 DOTween 사용 중. 예제 폴더는 불필요.
왜 삭제?
데모만 제거. DOTween 본체는 유지.
아카이브(사실상 치우기)Scenes 임시 씬들
뭐하는 것?
  • LobbyScene temp, LobbyScene_TEMPPPPP — 로비 작업 중 복사본/실험 씬
  • MainScene_Temp — 인게임 실험 씬
  • JmgScene, Trick2Scene — 개인/실험용으로 보이는 씬 (팀 확인)
정식 씬은?
LobbyScene(로비·캐릭터 선택), MainScene(실제 플레이).
왜 치우나?
임시 씬이 옆에 있으면 “어느 게 진짜?”가 됨. _Archive로 격리.

3 이동 대상 — 뭐 하는 것들이길래?

3-1. WeaponChoice (무기 선택 UI)

이동Scripts/WeaponChoice/ → Scripts/UI/WeaponChoice/
뭐하는 것?
레벨업·상자 등에서 무기 3장 중 고르는 UI 전체.
파일별
  • WeaponChoiceUI — 패널 열고 카드 3장 보여 줌
  • WeaponChoiceCard — 카드 한 장(이름/설명/레벨)
  • WeaponChoiceController — 언제 선택창을 띄울지 큐/흐름 관리
  • Cyborg/Hacker…DescriptionBuilder — 캐릭터별 설명 문장 만들기
왜 이동?
하는 일이 UI인데 Scripts 최상위에 혼자 떨어져 있음. Prefabs도 UI/Ingame 쪽에 있음.

3-2. Sound / Audio

이동Managers 안 Sound* → Scripts/Audio/
뭐하는 것?
게임 소리(BGM/SFX)를 재생·관리하는 코드들.
파일별
  • SoundManager — 사운드 시스템의 중심. 이벤트 정의/프로필 경로도 알고 있음
  • LobbySoundManager — 로비 씬 소리
  • InGameSoundManager / MainSceneSoundManager — 인게임 소리
  • ItemSoundManager — 아이템/픽업 관련 소리
  • GameSoundEventDefinition — “이 이벤트면 이 소리” 같은 데이터 정의
  • WeaponSoundProfileDefinition — 무기별 사운드 프로필 정의
왜 이동?
Managers에 너무 많이 섞여 있음. “소리”는 Audio 구역이 더 찾기 쉬움.

3-3. Lobby 스크립트

이동LobbyManager, LobbyCharacterSelector → Scripts/UI/Lobby/
뭐하는 것?
  • LobbyManager — 로비 씬 전체 흐름(화면 전환, 로비 상태)
  • LobbyCharacterSelector — 로비에서 캐릭터 고르기 쪽 로직
왜 이동?
로비 전용 UI/흐름인데 전역 Managers와 섞이면 “진짜 전역 매니저”와 구분이 안 됨.

3-4. 해킹 Prefabs

이동Prefabs/Objects/Hacking Objects/ → Prefabs/Hacking/
뭐하는 것?
맵에 두고 플레이어가 해킹으로 점령/발동하는 장치 프리팹들 + UI 조각.
프리팹별
  • ElectricFence — 전기 울타리 해킹 오브젝트
  • MagneticBeacon — 자기 비콘
  • SatelliteUplink — 위성 업링크
  • SecurityTurret — 보안 터렛
  • SynapseServer — 시냅스 서버
  • CaptureUI — 점령/캡처 진행 UI
  • HackInteractPrompt — “해킹하려면 …” 프롬프트
  • HackingObjectButtonTutorial — 튜토리얼용 버튼/안내
Scripts 쪽은?
이미 Scripts/Hacking/에 시스템·미니게임·이펙트가 있음. Prefabs만 Objects 아래라 이름이 안 맞음.
왜 이동?
같은 기능(해킹)은 같은 동네 이름(Hacking)으로.
참고: 해킹 Scripts가 하는 일 (이동 대상은 아님, 이해용)
HackingSystem = 해킹 전체 진행, HackableObject = 해킹 가능한 오브젝트, MiniGame/* = 해킹 미니게임들, Effects/* = 해킹 성공 후 발동 효과. 이건 이미 자리가 좋아서 유지.

4 유지 대상 — 뭐 하는 것들이길래?

4-1. Plugins 본체

유지Plugins/Demigiant (DOTween)
뭐하는 것?
UI 페이드, 연출 애니메이션을 코드로 쉽게 만드는 트윈 엔진.
왜 유지?
클리어/게임오버 UI 등에서 사용 중.
유지Plugins/Easy Save 3
뭐하는 것?
세이브/로드 플러그인 (ES3.Save / ES3.Load). 골드, 특성 레벨, 설정값 저장 등.
왜 유지?
TraitManager, SettingsManager, UI 골드 표시 등에서 사용 중.
유지Plugins/Sirenix (Odin Inspector)
뭐하는 것?
유니티 인스펙터를 강력하게 만드는 에디터 확장. 데이터 작업·디버그 생산성용.
왜 유지?
팀 작업 도구. 런타임 필수와 별개로 개발 효율에 중요.
유지Plugins/AllIn1SpriteShader
뭐하는 것?
2D 스프라이트에 효과(아웃라인, 히트 플래시 등)를 주기 쉬운 셰이더 팩.
왜 유지?
비주얼/머티리얼에서 사용. 1차에 제거하면 화면이 깨질 수 있음.
유지Plugins/Protobuf
뭐하는 것?
데이터 직렬화 포맷 Protocol Buffers 관련 파일 자리. (네트워크/바이너리 데이터용으로 흔히 씀)
왜 유지?
1차에 사용처 전수 확정이 어렵고, 플러그인 삭제는 사고 위험. 필요 시 2차 조사.
유지SerializableDictionary 본체
뭐하는 것?
인스펙터에서 편집 가능한 Dictionary/HashSet 유틸.
왜 유지?
예제만 지우고 라이브러리는 남김. (게임 Scripts에서 직접 using이 안 보여도, 다른 에셋/향후 사용 가능)

4-2. 게임 콘텐츠 동네

유지Scripts/Characters , Prefabs/Characters , Data/Characters
뭐하는 것?
플레이어(Cyborg/Hacker), 적, 보스, 버프/디버프, 스탯 — 캐릭터 관련 전부.
유지Scripts/Objects , Prefabs/Objects , Data/Objects
뭐하는 것?
드랍(경험치·골드·상자), 맵 오브젝트/기믹, 무기 프리팹·무기 스탯 CSV 등 월드/장비 오브젝트.
유지Scripts/Hacking (폴더 자체)
뭐하는 것?
해킹 시스템·미니게임·효과. NeoSurvive 핵심 시스템 중 하나.
유지Scripts/UI , Prefabs/UI
뭐하는 것?
HP바, 일시정지, 설정, 특성 UI, 클리어/게임오버, 로비 UI 프리팹 등 화면.
유지Scripts/Core
뭐하는 것?
카메라, 맵 타일 스폰, 페이즈/공성 이벤트, CSV 밸런스 로더 등 게임 뼈대.
유지Data/Balancing , Traits , Sounds
뭐하는 것?
Balancing = 적 스탯/스폰/경험치 CSV, Traits = 특성(업그레이드) JSON, Sounds = 사운드 이벤트 ScriptableObject.
유지Resources (애니/스프라이트/사운드/폰트/타일맵…)
뭐하는 것?
화면에 보이는·들리는 실제 에셋 저장소. 일부는 Resources.Load로 코드가 직접 부름.
왜 구조 유지?
경로 문자열 때문에 함부로 옮기면 런타임에 “못 찾음”.
유지LobbyScene.unity , MainScene.unity
뭐하는 것?
로비(시작·선택) / 인게임(생존 플레이) 정식 씬.
유지Settings/ (URP)
뭐하는 것?
2D URP 렌더러·파이프라인 에셋. 그래픽 출력의 기본 설정.
유지(팀 도구)ParrelSync , vFavorites
뭐하는 것?
ParrelSync = 같은 프로젝트를 복제해서 멀티플레이/동시 테스트하기 쉬운 에디터 도구. vFavorites = 에디터에서 자주 쓰는 에셋 즐겨찾기.
왜 유지?
빌드 게임플레이와 무관해도 개발 편의. 팀이 쓰면 유지.

5 보류 대상 — 뭐 하는 것들이길래?

보류Resources/Sprites/archive/ , UI/Archive/
뭐하는 것?
예전에 쓰였거나 후보로 받아 둔 스프라이트 더미/아카이브. 폭발, 마법, UI 조각 등 대량 이미지.
왜 보류?
파일이 수천 개라 지우고 싶지만, 어딘가 참조가 남아 있을 수 있음. 확인 후 삭제/격리.
보류Resources/Sounds/SFX/temp/
뭐하는 것?
임시로 넣어 둔 효과음 후보.
왜 보류?
실제 재생 경로에 연결됐는지 확인 필요.
보류공백 있는 폴더명 (Map Objects, Drop Objects…)
뭐하는 것?
맵 기믹/드랍 오브젝트 등 정상 콘텐츠 폴더. 이름에 공백만 문제.
왜 보류?
리네임은 경로 하드코딩·습관을 많이 깨뜨림. 폴더링 안정화 후.
보류Resources → Art 이전, namespace 통일, asmdef
뭐하는 것?
구조 개선·코드 규약 작업. “정리”가 아니라 리팩터/아키텍처에 가까움.
왜 보류?
1차 임무(폴더·파일 관리) 범위 밖.
보류이상한 Prefab 파일명 / 끝 공백
뭐하는 것?
프리팹 자체는 게임 오브젝트 틀. 이름만 지저분하거나 공백이 들어간 경우.
왜 보류?
이름만 바꿔도 참조가 깨질 수 있어 폴더 이동과 같은 날에 하지 않음.

6 Packages — 각각이 뭐 하는 건지

주의
여기 목록은 Packages/manifest.json 기준입니다. 1차에 삭제하지 않고, “역할 이해 + 보류/유지”만 합니다.
유지com.unity.render-pipelines.universal (URP)
뭐하는 것?
유니티의 렌더 파이프라인. 2D/현대적 렌더링의 기반.
유지com.unity.feature.2d
뭐하는 것?
스프라이트, 타일맵, 2D 물리 등 2D 게임 기능 묶음.
유지com.unity.textmeshpro / ugui
뭐하는 것?
텍스트(TMP)와 UI 시스템. 버튼·패널·글자 표시의 뼈대.
유지com.unity.test-framework / ide.*
뭐하는 것?
테스트 실행, Rider/Visual Studio 연결. 개발 도구.
유지com.gameanalytics.sdk
뭐하는 것?
플레이 데이터 분석 SDK. 플레이 시작, 해킹 결과 등 이벤트 전송.
유지com.coplaydev.unity-mcp
뭐하는 것?
에디터를 외부 AI/툴과 연결하는 MCP. 지금 팀이 쓰는 작업 도구.
보류com.unity.visualscripting
뭐하는 것?
노드 그래프(비주얼 스크립트)로 로직을 짜는 유니티 기능.
왜 보류?
우리 게임 그래프는 거의 안 보임. 다만 Easy Save 등이 관련 코드를 포함할 수 있어 바로 제거 금지.
보류com.unity.localization
뭐하는 것?
다국어(한/영 등) 문자열 테이블을 관리하는 패키지.
왜 보류?
게임 쪽 번역 테이블은 안 보이지만 Odin Localization 모듈과 엮일 수 있음.
보류NuGetForUnity (+ 빈 packages.config)
뭐하는 것?
C# NuGet 라이브러리를 유니티로 가져오는 도구.
왜 보류?
지금 설치된 NuGet 패키지가 비어 있음. 앞으로도 안 쓰면 제거 후보.
보류NativeWebSocket
뭐하는 것?
웹소켓 통신 라이브러리. 실시간 서버 연결용으로 많이 씀.
왜 보류?
게임 Scripts에서 직접 사용이 바로 안 보임. 멀티/서버 계획 여부 확인 후.
보류Timeline / Project Auditor
뭐하는 것?
Timeline = 컷신/연출 트랙. Project Auditor = 프로젝트 성능·문제 분석 도구.
왜 보류?
팀에서 쓰는지 확인 후 유지/제거.
유지(보통)EDM (External Dependency Manager)
뭐하는 것?
안드로이드/iOS 네이티브 의존성을 맞춰 주는 Google 쪽 매니저. 모바일 SDK와 자주 같이 옴.

7 Managers 안 스크립트 — 각각 뭐 함? (이동/유지 구분)

“Managers에 있다고 다 같은 종류”가 아닙니다. 역할표입니다.

스크립트뭐 하는 것?1차

TraitManager특성(영구/메타 업그레이드) 관리·세이브유지
SettingsManager해상도·볼륨·옵션 저장/적용유지
ManagerInitializer매니저들 초기화 순서유지
DistanceManager거리 관련 계산/관리유지
