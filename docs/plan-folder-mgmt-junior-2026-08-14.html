1 한 줄 목표

1차 임무: 규칙 정하고 → 확실한 쓰레기만 치우고 → Scripts/Prefabs 자리만 맞춘다.
Packages·Resources·Data 큰 정리는 조사 후 2차.
하는 것
빈 폴더 삭제, 예제/temp 정리, WeaponChoice·Audio·Hacking 위치 맞추기
안 하는 것
코드 로직 변경, namespace 통일, Packages 막 삭제, Resources 전체 이동

2 시니어가 생각하는 법

유니티 폴더 정리는 “예쁘게”가 목표가 아닙니다. 목표는 세 가지뿐입니다.

1. 찾기 쉽게
“해킹이면 Hacking”처럼 이름이 같아야 신입도 바로 찾습니다.
2. 가볍게
안 쓰는 예제·아카이브·빈 폴더가 있으면 찾기·빌드가 느려집니다.
3. 안 부수기
지웠다가 게임 깨지면 안 됩니다. 확실한 것부터, 작게 합니다.
순서
규칙 → 쓰레기 치우기 → 이름/위치 맞추기 → (나중에) 큰 정리·코드 리팩터
주니어에게 매번 말할 문장
“이건 삭제야, 이유: ___ / 이건 이동이야, 이유: ___ / 이건 아직 둬, 이유: ___”

3 폴더 규칙 (초간단)

게임을 구역(도메인)으로 나눕니다. 같은 구역이면 Scripts / Prefabs / Data에서도 비슷한 이름을 씁니다.

구역 이름쉽게 말하면
Characters플레이어, 적
Objects드랍, 맵 기믹, 무기 프리팹 등
Hacking해킹 시스템
UI화면, 버튼, 패널
Audio소리
Data숫자/설정 데이터 (CSV, SO)
Scenes씬
좋은 예
Scripts/Characters
↔ Prefabs/Characters
↔ Data/Characters
나쁜 예
스크립트는 Hacking
프리팹은 Objects/Hacking Objects
→ 같은 기능인데 찾는 길이 다름

비유: 부서 이름을 팀마다 다르게 부르면 신입이 서류를 못 찾습니다. 폴더도 똑같습니다. 이게 바로 “같은 도메인 언어”입니다.

5 삭제할 것 (1차 후보)

“왜 지우냐?”에 바로 답할 수 있는 것만 모았습니다.

삭제 Scripts/Items/

왜? 안에 파일이 없음(빈 상자). 있으면 있을 것 같아서 헷만 줌.

삭제 Scripts/Hacking/ObjectManager/ , Reward/

왜? 빈 폴더. 해킹 코드는 이미 다른 하위 폴더에 있음.

삭제(조건부) Scripts/Characters/Player/Weapon/Passive/

왜? 비어 있음. 패시브 무기 폴더를 앞으로 쓸 계획 없으면 삭제. 쓸 거면 유지.

삭제 Prefabs/Managers/ (비어 있으면)

왜? 빈 프리팹 폴더. 필요해지면 그때 다시 만들면 됨.

삭제 Assets/Packages/ (빈 폴더)

왜? 진짜 패키지는 프로젝트 루트 Packages/에 있음. Assets 안 빈 Packages는 헷갈리게만 함.

삭제 추천 TextMesh Pro/Examples & Extras/

왜? TMP가 넣어 준 샘플. 우리 게임 UI가 아님. 용량·검색 노이즈만 생김. (~249 files)

삭제 추천 SerializableDictionary/Example/

왜? 플러그인 예제 씬/스크립트. 게임에서 안 씀. 코어(SerializableDictionary.cs)는 유지.

삭제 추천 Plugins/Demigiant/DOTweenPro Examples/

왜? DOTween 예제. 게임은 DOTween을 쓰지만 예제 폴더는 필요 없음.

삭제 대신 아카이브 Scenes/*temp* , *_TEMP* , MainScene_Temp

왜? 작업하다 남은 임시 씬. 정식은 LobbyScene, MainScene만. 바로 영구 삭제보다 먼저 Scenes/_Archive/로 옮기는 게 안전.

삭제 보류(확인 후) Resources/Sprites/archive/ , UI/Archive/ , Sounds/SFX/temp/

왜 눈에 띄나? 파일이 엄청 많음(수천 개). Resources 안이면 빌드/임포트에 부담. 왜 1차에 바로 안 지움? 어딘가에서 쓰일 수도 있음. 참조 확인 후 2차에서 삭제/격리.

6 이동할 것 (1차)

코드 내용은 안 바꿉니다. 자리만 옮깁니다. .meta도 반드시 같이.

지금어디로왜 옮기나 (쉽게)
Scripts/WeaponChoice/ Scripts/UI/WeaponChoice/ 무기 선택 화면인데 UI 밖에 혼자 있음
Managers/*Sound* + Managers/Audio/ Scripts/Audio/ 소리는 Managers가 아니라 Audio 구역이 맞음
Managers/LobbyManager 등 Scripts/UI/Lobby/ 로비 UI/흐름용. 전역 Managers와 섞이면 찾기 힘듦
Prefabs/Objects/Hacking Objects/ Prefabs/Hacking/ Scripts는 이미 Hacking. 이름 맞추기
temp 씬들 Scenes/_Archive/ 버리지 않고 치워 두기

Managers에 남는 것 (예시)

진짜 “게임 전체 관리자”만 남깁니다.

GameManager, DataManager, MapManager, UIManager, UpgradeManager, TraitManager, SettingsManager, ManagerInitializer 등

이동할 때 절대 규칙
파일과 .meta를 같이 이동해야 합니다. Unity는 경로보다 GUID로 연결합니다. meta를 잃으면 Missing이 납니다.

7 유지할 것

유지Plugins/ (Odin, Easy Save, DOTween, AllIn1…)

왜? 게임/툴이 실제로 사용 중. 1차에 손대면 사고 큼.

유지Data/ 구조 (CSV, 캐릭터/무기 SO)

왜? 코드에 경로가 박혀 있음(BalancingSheetCatalog 등). 옮기면 코드 수정 = 리팩터.

유지Resources/ 전체 위치 (1차)

왜? Resources.Load("…") 문자열이 있음. 폴더 옮기면 런타임에 못 찾음.

유지LobbyScene.unity , MainScene.unity

왜? 정식 빌드 씬.

유지Settings/ (URP 설정)

왜? 렌더 파이프라인 설정. 게임 필수.

유지(팀 편의)ParrelSync , vFavorites

왜? 에디터 작업 도구. 빌드에 거의 안 들어가지만 팀이 쓰면 유지.

8 보류할 것 (2차 이후)

보류공백 폴더명 (Map Objects, Drop Objects…)

왜 나중에? 이름 바꾸면 하드코딩 경로·습관이 많이 깨짐. 폴더링 안정화 후.

보류namespace 통일 / Managers 코드 분리 / asmdef

왜 나중에? 그건 리팩터. 이번 임무는 폴더·파일 관리.

보류Resources → Art 이전

왜 나중에? 파일 ~7500개 + Load 경로. 별도 조사·승인 필요.

보류깨진/이상한 Prefab 파일명, trailing space

왜 나중에? 리네임은 참조 리스크. 폴더 이동과 같은 PR에 넣지 말 것.

9 Packages 폴더 점검

여기 말하는 Packages는 프로젝트 루트 Packages/manifest.json 입니다. (Assets/Packages 빈 폴더와 다름!)

1차 규칙
Packages를 막 삭제하지 않습니다. 컴파일·에디터가 한꺼번에 깨질 수 있습니다. 1차는 목록만 정리, 제거는 2차(팀 확인 후).
패키지판단쉽게 말하면
URP, 2D, TMP, uGUI, Test, IDE 유지 엔진/툴 기본. 없으면 프로젝트 성립 안 됨
GameAnalytics 유지 코드에서 이벤트 추적 사용 중
unity-mcp 유지 에디터 MCP 툴
visualscripting 보류 게임 그래프는 거의 안 보임. Easy Save가 참조할 수 있음 → 조사 후
localization 보류 게임 번역 테이블은 안 보임. Odin 모듈과 관련 가능
NuGetForUnity + 빈 packages.config 보류 지금 NuGet 패키지 비어 있음. 제거 여부는 팀 확인
NativeWebSocket 보류 게임 코드 사용 여부 재확인 후
Timeline / Project Auditor 보류 쓰면 유지, 안 쓰면 나중에 제거

Plugins 쪽 DOTween / Easy Save / Odin은 Package Manager가 아니라 Assets/Plugins에 들어 있는 에셋입니다. 1차 유지.

10 1차 작업 순서 (이렇게 한다)

Step 0 — 규칙·결정 합의

이동 없음
D1~D5 답을 받습니다. 이 HTML이 기준 문서가 됩니다.

Step 1 — 확실한 삭제·씬 아카이브

청소
빈 폴더, TMP Examples, Dictionary Example, DOTween Examples, temp 씬 → _Archive. Build Settings에서 죽은 씬 경로 정리.

Step 2 — Scripts 이동

이동
WeaponChoice → UI, Sound → Audio, Lobby → UI/Lobby. 컴파일 0에러 + Lobby/Main/무기선택/사운드 스모크.

Step 3 — Prefabs 이동

이동
Hacking Objects → Prefabs/Hacking. 해킹 상호작용 스모크.

Step 4 — 리포트만 (삭제 X)

보류 목록
Resources Archive 사용 여부, Packages 제거 후보를 문서로 남기고 팀 확인 후 2차 진행.

12 주니어 체크리스트 · 스모크

작업할 때마다

  • 이건 삭제 / 이동 / 유지 / 보류 중 어디에 넣었는지 말할 수 있다
  • 삭제·이동 이유를 한 줄로 적을 수 있다
  • .meta를 같이 옮겼다
  • Plugins / Data 대이동 / Resources 대이동을 이번 PR에 안 넣었다

스모크 (이동 PR 공통)

  • Compile Error 0
  • LobbyScene 로드 + 캐릭터 선택
  • MainScene 진입 + 이동/공격
  • 무기 선택 UI 1회 (Scripts 이동 후)
  • 해킹 상호작용 1회 (Prefabs 이동 후)
  • Missing Script / Missing Prefab 없음
구현 시작 조건
D1~D5 확정 + 주인님의 HTML OK / 구현 진행 / 승인
