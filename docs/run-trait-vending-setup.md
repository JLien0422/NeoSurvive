# RunTrait 자판기 기반 복원

Git의 `2a2c12d4`에 남아 있던 RunTrait 코드를 기반으로 복원했습니다.
실버 45%, 골드 30%, 플래티넘 25% 기본 확률과 중첩 수에 따른 추첨 가중치를 유지합니다.
플래티넘은 한 런에서 한 번만 획득하며, 후보는 중복 없이 최대 3개입니다.

## 노션 특성을 에셋으로 옮기기

1. Project 창에서 Create → NeoSurvive → Traits → Run Trait Definition을 선택합니다.
2. 고유 `traitId`, 표시 이름, 설명, 아이콘, 등급, 대상 캐릭터, 최대 중첩을 입력합니다.
3. 공통 특성은 `isCommonTrait`을 체크합니다.
4. `Assets/Data/RunTraitCatalog.asset`의 Traits 목록에 특성 에셋을 추가합니다.

카탈로그에 첨부 기획의 새 해커 15종·사이보그 15종을 등록했습니다.
특성 에셋은 `Assets/Data/RunTraits/Hacker`와 `Assets/Data/RunTraits/Cyborg`에 있습니다.
기본 기획에 따라 실버 5회·골드 3회·플래티넘 1회 획득 제한을 사용합니다.
아이콘은 각 특성 에셋에서 지정합니다. 앞부분의 구 특성·공용 유물 목록은 이번 카탈로그에 포함하지 않았습니다.
데이터 클래스와 파일 이름을 일치시키기 위해 Definition, Catalog를 별도 스크립트로 분리했습니다.
복원한 Manager와 Tier, SynergyTag는 기존 메타 GUID를 유지합니다.

## 씬 연결

- `Zapanki.prefab`에 특성 카탈로그와 `TraitChoicePanel .prefab`을 연결했습니다.
- 패널은 `TraitChoiceUI`, 카드는 `TraitChoiceCard`로 교체했고 UI 요소 참조는 유지했습니다.
- 기존 무기 선택 UI 스크립트는 원래의 무기 전용 코드로 되돌렸습니다.
- `Choice UI`가 비어 있으면 `Choice UI Prefab`을 Canvas 아래에 생성합니다.
- Canvas가 여러 개면 자판기의 `UI Canvas`에 인게임 Canvas를 직접 지정합니다.
- 이미 씬에 있는 패널을 쓰려면 `Choice UI`에 해당 인스턴스를 지정합니다.
- 비워두면 비활성 패널도 포함해 씬의 `TraitChoiceUI`를 찾습니다. Canvas 밖에 있는 패널은 표시 전에 Canvas 아래로 옮깁니다.
- E 표시에는 기존 `HackInteractPromptAnchor`와 씬의 `HackingSystem` 프롬프트 설정을 사용합니다.
- 선택 UI 버튼 및 닫기는 코드에서 연결하므로 UnityEvent 목록을 채울 필요가 없습니다.

첫 이용 시 Manager가 없으면 플레이어에 추가하고 카탈로그로 초기화합니다.
같은 런의 다른 자판기는 기존 획득 상태를 공유합니다.
현재 기본 흐름은 플레이어가 씬 재시작 때 새로 생성되는 구조를 기준으로 합니다.
플레이어를 유지하면서 새 런을 시작한다면 시작 지점에서 `InitializeRun(selectedCharacter)`를 호출해야 합니다.
골드 차감, ES3 저장, 기존 TraitManager는 이 자판기 흐름에서 사용하지 않습니다.

## 효과 구현 범위

후보 생성, 획득 상태, UI 선택 연결 및 피해 3종·공격 주기와 범위 9종·상태이상과 증폭 및 설치 8종·플래티넘 특수 효과 10종을 전투 코드에 연결했습니다. 실제 Unity Play Mode 검증은 별도입니다.
`RunTraitDefinition.effect` 배열에 효과 ScriptableObject를 여러 개 연결할 수 있습니다. 공유 에셋에는 설정과 계산 규칙만 저장합니다.
단일 효과 참조로 저장되어 있던 특성 30개를 배열 직렬화 형태로 변환했습니다.
획득 레벨은 Manager에 있으며 특성을 획득하거나 새 런을 시작해도 SO 원본을 수정하지 않습니다.
`Assets/Data/RunTraits/Effects/DamageBonus10Percent.asset`을 조준 링크·유압 참격·탄도 증폭이 공유합니다.
각각 사격·근접·원거리 태그의 무기 피해에 장당 10%, 최대 50%를 적용합니다.
`Character.TakeDamage(amount, sourceWeapon)`에서 Enemy와 Boss에게 들어가는 피해에 적용하며 피해 통계에도 보정값을 기록합니다.
기존 연쇄 방전에는 런 특성 보정 전 값을 전달하여 다음 대상에서 배율이 중복되지 않게 합니다.
무기 출처가 null인 피해, 플레이어가 받는 피해, Character를 거치지 않는 IDamageable 경로에는 적용하지 않습니다.
새 특성 30종의 effect 배열에 모두 실행용 SO를 연결했습니다.
범위·CC·증폭·설치 등 나머지 특성을 피해 증가로 처리하지 않습니다.
무기 에셋 20개에는 기획표의 시너지 태그 2개씩을 등록했습니다.
현재 `requiresWeaponTag`는 태그에 따른 피해·수치 보정용이며, 보유 무기의 태그로 후보를 제한하지 않습니다.

## 공격 주기·범위 효과 SO

`WeaponStatModifierEffect`의 Modifiers에 적용 수치 종류와 장당 비율을 설정합니다.
예를 들어 주기 -10%는 `AttackInterval / -0.1`, 각도 +10%는 `AttackAngle / 0.1`입니다.
동일 특성에서 설치 쿨타임 감소와 드론 추종속도 증가처럼 서로 다른 수치를 함께 설정할 수 있습니다.
새 에셋은 Create → NeoSurvive → Traits → Effects → Weapon Stat Modifier에서 만듭니다.

| 연결한 특성 | 실제 적용 |
|---|---|
| 연사 회로 | 피스톨·라이플·드론·설치된 포탑의 공격 주기 -10%/장 |
| 순환 가속 | 라이플·스크램블러·디지털 실드·수류탄의 공격 주기 -10%/장 |
| 배포 가속 | 포탑·펄스·최적화·디코이 설치 쿨타임 -10%/장, 드론 추종속도 +10%/장 |
| 구동 가속 | 소드·서지·너클 공격 주기 및 톱 타격 간격 -10%/장 |
| 역장 가속 | 해머 공격 주기, 테슬라 오라 틱·번개 주기 -10%/장, 실드 회전속도 +10%/장 |
| 확산 노드 | 라이플 사거리·두께, 스크램블러 사거리·각도, 디지털 실드 타격 반경, 수류탄 폭발 반경 +10%/장 |
| 확장 각도 | 소드·해머 각도, 서지 찌르기 사거리 +10%/장. 해머 사거리는 제외 |
| 사정 연장 | 포톤·너클·볼트 사거리, 투사체의 탄속, 톱 이동속도, 브레스 사거리·폭 +10%/장 |
| 역장 팽창 | 실드 회전반경, 해머 사거리, 테슬라 오라 반경 +10%/장 |

무기의 기본값·CSV·SO 원본은 변경하지 않고 실행 지점에서 현재 배율을 읽습니다.
이미 생성된 포탑·투사체·브레스 판정도 다음 공격·업데이트에 현재 배율을 읽습니다.
사격·광역 태그를 함께 가진 라이플은 연사 회로와 순환 가속을 가산합니다. 각각 3중첩이면 기본 주기의 40%입니다.
주기 배율의 최솟값은 10%로 제한해 설정값을 크게 바꿔도 0초·음수 주기가 되지 않게 합니다.
포톤은 현재 순간 빔 방식이므로 사거리·빔 표시 길이를 늘리며 별도의 비행 시간을 만들지 않습니다.
라이플은 기존 특성이 없을 때 선 판정을 유지합니다. 두께 효과가 있으면 `PlasmaLazer.beamHitWidth`(기본 0.1)에 배율을 적용한 BoxCast를 사용합니다.
라이플의 마스터 분열탄은 원본의 보정 전 두께에서 시작해 두께 배율이 중복되지 않게 합니다.

## 상태이상·증폭·설치 효과 SO

| 특성 | 연결한 효과 |
|---|---|
| 지속 교란 | 혼란·수류탄 기절·디코이 감옥·실드 넉백 시간과 교란 감속 지속시간 +10%/장 |
| 심층 교란 | 교란 무기 적중 시 감속 +10%p/장, 실드 넉백 거리 +10%/장 |
| 오버레이 | 최적화 필드와 피스톨 마스터 표식의 증폭에 +10%p/장 |
| 버퍼 유지 | 필드·표식 증폭 지속시간과 최적화 필드 수명 +10%/장 |
| 상주 프로세스 | 포탑·펄스·최적화 필드 수명, 드론 탐지 범위, 디코이 최대 체력 +10%/장 |
| 충격 가중 | 소드·서지·너클·톱의 신규 넉백과 거리 +10%/장. 톱은 플레이어 반대 방향 |
| 전도 감속 | 에너지 무기 적중 시 감속 +10%p/장. 기존 포톤·브레스 감속에 가산하며 상한은 90% |
| 잔광 유지 | 에너지 감속 및 기존 기절·속박 등의 지속시간 +10%/장 |

`OnHitStatusEffect`는 신규 감속·넉백의 기본값을 저장합니다.
기획에서 미정이던 신규 감속은 기본 1초, 신규 넉백은 속도 4·시간 0.15초로 설정했습니다. 에셋에서 조정할 수 있습니다.
`WeaponStatModifierEffect`에는 기존 시간·체력·탐지 배율과 %p 증폭을 설정합니다.
심층 교란의 effect 배열에는 감속 SO와 넉백 거리 SO를 각각 연결했습니다.

계산 예시:

- 기본 감속 30%(이동 배율 0.7)에 감속 +50%p를 더하면 최종 감속 80%(배율 0.2)입니다.
- 기본 증폭 20%(피해 배율 1.2)에 증폭 +50%p를 더하면 최종 증폭 70%(배율 1.7)입니다.
- 최적화 필드는 상주 프로세스 5중첩과 버퍼 유지 3중첩을 함께 받으면 수명이 기본의 1.8배입니다.
- CC 시간이 늘어나는 실드는 같은 거리에서 더 오래 밀리도록 속도를 조정합니다. 시간 증가가 넉백 거리까지 다시 늘리지 않습니다.

신규 감속은 `RunTraitSlowReceiver`가 런타임에서 관리합니다. 동일 출처는 갱신하고, 여러 무기는 가장 강한 감속을 사용합니다.
소스별 만료를 처리하고 비활성화 때 자신이 적용한 배율을 제거합니다. SO에 타이머나 대상 상태를 저장하지 않습니다.
기존 포톤·브레스의 감속도 같은 경로로 합쳐 중복 적용하지 않습니다.
이미 적용된 기절·혼란·속박의 남은 시간을 소급 수정하지는 않습니다. 다음 적중·상태 갱신부터 새 배율을 사용합니다.
이미 생성된 포탑·펄스·필드의 수명, 드론 탐지, 표식의 수명·증폭은 현재 배율을 읽습니다.
디코이 최대 체력이 변하면 현재 체력 비율을 유지합니다. 초기화 때 최대·현재 체력을 함께 설정해 첫 피해 때 체력이 기본값으로 잘리는 문제를 막았습니다.
필드가 자신의 무기 출처를 전달하도록 고쳤으며, 안에 있는 적의 증폭은 0.2초 간격으로 갱신합니다. 재갱신 때문에 증폭이 계속 곱해지지 않습니다.

### 상태 계열 검증

- `Tools/RunTraitValidation/run.ps1`: 총 179개 계산·데이터·상태 갱신 검사 통과. 실제 효과 에셋과 런타임 소스를 사용하며 Unity API는 대체 구현입니다.
- 감속 %p 합산·상한·강도 우선순위·반복 적중·만료·비활성화 복구, 증폭 가산, 설치 수명·체력·탐지 채널, 여러 효과 SO 및 런 초기화를 검사했습니다.

- 플레이 중 오버레이 1중첩에서 증폭이 20%→30%인지, CC 5중첩에서 시간이 1.5배인지, 감속 중복이 계속 곱해지지 않는지 확인해야 합니다.
- 디코이가 피해를 받은 상태에서 상주 프로세스를 획득했을 때 HP 비율이 유지되는지, 설치물 중간 획득 때 수명이 연장되는지도 확인해야 합니다.

## 플래티넘 특수 효과 SO 10종

공통 `SpecialTraitEffect` 스크립트로 서로 다른 효과 SO 10개를 만들었습니다.
에셋은 `Assets/Data/RunTraits/Effects`에 있으며 해당 플래티넘 Definition의 effect 배열에 연결했습니다.
Create → NeoSurvive → Run Trait → Platinum Special Effect로 추가하고 Kind를 지정할 수 있습니다.
Kind, 효율, 거리, 지연, 경직 쿨, 연쇄 횟수, 보호막 설정은 SO에 있습니다.
공격 스냅샷, 방문 대상, 타이머, CC 출처, 보호막 잔량은 실행 객체에 있습니다.

| 특성 / SO | 실제 연결 |
|---|---|

## 원하는 특성을 직접 적용하는 디버그 창

1. Unity 메뉴에서 **Tools → NeoSurvive → 특성 테스트**를 엽니다.
2. MainScene을 Play Mode로 실행합니다. 플레이어가 생성되면 현재 캐릭터의 특성이 표시됩니다.
3. 이름 또는 ID로 검색하거나 실버/골드/플래티넘 등급을 선택합니다.
4. **+1**은 한 단계 획득하며, **최대**는 해당 특성의 남은 중첩을 모두 획득합니다.
5. **-1**은 해당 특성의 중첩을 한 단계 제거합니다. 플래티넘은 한 번 누르면 해제됩니다.
6. **획득한 특성 전체 초기화**는 검색/등급 필터와 무관하게 현재 런의 모든 특성을 제거합니다.
7. 행의 `Lv.현재/최대`와 하단 적용 메시지, Console의 `[RunTraitDebug]` 로그로 결과를 확인합니다.

기본 카탈로그는 자동 연결됩니다. 현재 런이 별도 카탈로그를 사용하면 그 런의 카탈로그를 표시합니다.
자판기를 아직 사용하지 않았어도 첫 적용 시 플레이어에 RunTraitManager를 만들고 초기화합니다.
현재 캐릭터 필터를 꺼서 다른 캐릭터의 특성을 볼 수 있지만, 획득은 현재 캐릭터에 맞는 특성만 가능합니다.
자판기의 특성 선택 창이 열려 있으면 먼저 닫아야 합니다.

## 기획 해석과 미정 수치

- 설치 실버의 상세 표에는 `피해 +10%`라는 칸이 있지만 효과 설명과 티어별 요약은 피해 증가를 명시적으로 제외합니다. 지속시간·탐지 범위·체력으로 정리했습니다.
- 설치 골드의 상세 표에는 드론 추종 `+1개체`라는 칸이 있지만 설명과 요약은 추종속도 +10%입니다. 추종속도로 정리했습니다. 드론 추가 1기는 플래티넘에만 있습니다.
- 최적화 증폭 20%에 +50%p를 더하면 70%이며, `70%p`는 최종 수치를 표현하는 표기로 사용하지 않았습니다.
- 신규 넉백·감속 기본값은 위 SO 기본값으로 구현했습니다. 플래티넘 경직 시간·내부 쿨타임에는 아래 시험값을 사용합니다.
- 역장 흡수의 비율·상한·감소는 기획 확정값이 아니며 아래 SO 시험값입니다.
- 등급 소진 시 낮은 등급에 2/3, 높은 등급에 1/3 배분하기로 사용자가 확정했습니다. 실버 소진은 0/60/40, 골드 소진은 65/0/35, 플래티넘 소진은 약 61.67/38.33/0입니다. 한 등급만 남으면 해당 등급만 등장합니다.
