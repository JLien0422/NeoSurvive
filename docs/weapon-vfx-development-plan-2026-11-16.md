# NeoSurvive 무기 이펙트 개발 기획서

작성일: 2026-11-16  
대상 브랜치: `dev/synergy`  
목적: 현재 무기별 피격 이펙트를 유지하면서 위치·속도·형태를 개선하고, 이후 발사·이동·종료 이펙트를 안전하게 확장한다.

## 1. 현재 상태와 병합 전 확인

- 현재 `dev/synergy`의 HEAD와 `origin/dev/synergy`는 `dc2c5565`로 동일하다.
- 작업 트리에는 `origin/backup/local-2026-11-10`(`09bf8ae9`) 병합이 이미 적용되어 있으며, 아직 병합 커밋은 생성하지 않은 상태다.
- 따라서 새 pull/merge를 다시 실행하지 않는다. 먼저 현재 병합 결과의 누락 참조와 Play Mode 회귀를 확인해야 한다.
- 지난 “백업” 병합의 데이터 누락은 단순 충돌 누락만의 문제가 아니다. 해당 원격 커밋 자체에 저장소에서 찾을 수 없는 GUID 참조가 포함되어 있으므로, 원본 작업자에게 관련 에셋과 `.meta`를 함께 받아야 한다.
- 현재 확인된 주요 위험 참조는 Tesla Coil 장판 프리팹, Data Scrambler Animator Controller, MainScene Volume Profile, 일부 폰트/TMP 에셋과 자판기 오브젝트다. 임의의 다른 파일로 GUID를 대체하지 않는다.

### 병합 완료 조건

1. 누락된 원본 파일과 대응 `.meta`를 같은 폴더 구조로 받는다.
2. Unity 재임포트 후 Missing Script, Missing Prefab, Missing Font를 확인한다.
3. 로비 → 캐릭터 선택 → 게임 진입 → 무기 선택 → 전투 흐름을 Play Mode로 확인한다.
4. 해커/사이보그 시너지 UI와 기존 피격 이펙트가 유지되는지 확인한다.
5. `git diff`에서 의도하지 않은 `.meta` 재기록과 대량 삭제가 없는지 확인한다.
6. 위 검증 후에만 병합 커밋 여부를 결정한다.

## 2. 현재 적용된 이펙트 구조

- 원본 보관: `Assets/Art/Animations/Objects/Weapons/Shared/Hun0fxOriginal/`
- 게임용 런타임 리소스: `Assets/Art/Animations/Objects/Weapons/Shared/Hun0fx/Runtime/`
- 공통 연결 스크립트: `Assets/Scripts/Characters/Player/Weapon/WeaponHitVfx.cs`
- 무기별 연결 위치: 각 무기 프리팹의 `WeaponHitVfx` Inspector 값
- 기존 피격 이펙트 연결 내역: `docs/weapon-vfx-2026-11-10.md`

현재 방식은 피해 코드는 그대로 두고, 피해가 확정된 지점에서 `Play` 또는 `PlaySustained`를 호출한다. 이 구조는 무기 로직을 크게 건드리지 않는 장점이 있다. 다만 `PlaySustained`도 이펙트를 적의 현재 월드 좌표에 한 번 생성할 뿐 적을 따라가지 않으므로, 빠르게 이동하는 적에게는 타격 후 이펙트가 뒤에 남아 보일 수 있다. 또한 짧은 lifetime에 전체 원본 프레임을 맞추기 위해 Animator 배속이 자동으로 올라가므로 일부 효과가 너무 빠르게 보인다.

## 3. 연출을 다섯 단계로 분리한다

모든 무기에 다섯 단계를 강제하지 않고, 필요한 단계만 선택한다.

| 단계 | 역할 | 배치 기준 | 예시 |
| --- | --- | --- | --- |
| 예고 | 공격 범위와 방향을 사전에 전달 | 공격자·바닥·목표 범위 | 망치 착지 원, EMP 범위선 |
| 발사 | 무기가 실제로 나갔음을 전달 | 총구·손·드론·포탑 | 총구 섬광, 전기 충전 |
| 이동 | 투사체의 속성·방향·사거리를 전달 | 투사체 또는 빔 | 탄 꼬리, 레이저, 수류탄 궤적 |
| 피격 | 피해가 들어간 위치와 속성을 전달 | 충돌점·적 중심·지면 | 스파크, 절단, 폭발 |
| 종료 | 지속 공격 종료 또는 잔류 상태를 전달 | 마지막 타격점·장판 | 연기, 잔광, 방전 소멸 |

피격 이펙트는 “피해 확인”이 우선이고, 발사·이동 이펙트는 “무슨 공격이 오는지”를 보여주는 역할로 분리한다. 같은 정보를 중복해 화면을 덮지 않는다.

## 4. 위치와 추적 방식

| 방식 | 적용 대상 | 규칙 |
| --- | --- | --- |
| 충돌점 고정 | 총알, 검, 볼트 | `ClosestPoint` 또는 실제 충돌 좌표에 1회 생성한다. 적을 따라가지 않는다. |
| 짧은 목표 추적 | 체인소, 브레스, EMP 지속 피해 | 0.15~0.35초 동안 적의 렌더러 중심 또는 콜라이더 중심을 따라간 뒤 제거한다. |
| 공격 방향 정렬 | 검격, 넉백, 빔 | 공격 벡터에 맞춰 회전한다. 45도 원본 시점 보정은 프리팹에서 유지한다. |
| 범위 중심 고정 | EMP, 망치, 수류탄 | 실제 피해 범위 중심에 생성하고 범위 반경과 스케일을 연결한다. |
| 지면 투영 | 장판, 낙뢰, 폭발 잔류물 | 적 중심이 아니라 바닥 좌표에 고정한다. 정렬 순서를 캐릭터보다 뒤로 둔다. |
| 길이 연동 | 레이저·빔 | 실제 사거리와 충돌 거리 중 짧은 값으로 길이를 정한다. 빈 공간을 뚫고 지나가지 않는다. |

목표 추적은 모든 효과에 적용하지 않는다. 단발 충돌은 월드에 남아야 타격 위치가 분명하며, 지속 접촉 효과만 짧게 따라가야 한다.

## 5. 시간 기준

아래 값은 첫 QA용 기준이며, 실제 공격 주기와 화면 밀도를 보고 Inspector에서 조정한다.

| 유형 | 권장 표시시간 | 반복 기준 |
| --- | ---: | --- |
| 빠른 총탄·드론 탄 | 0.16~0.24초 | 같은 적에게 0.12~0.20초 쿨다운 |
| 일반 검격·볼트 | 0.22~0.35초 | 피해 1회당 1회 |
| 중량 타격·망치 | 0.35~0.55초 | 착지 또는 강타 1회당 1회 |
| 수류탄·범위 폭발 | 0.45~0.75초 | 폭발 판정 1회당 1회 |
| 체인소·브레스·지속 빔 | 0.25~0.45초 | 매 데미지 틱 생성 금지. 하나를 유지하거나 0.25~0.45초마다 갱신 |
| 상태이상 잔류 | 0.5~1.2초 | 상태가 길어도 약한 루프 1개만 유지 |

원본 애니메이션은 프레임을 생략하지 않는다. 대신 `클립 길이 / lifetime`으로 무조건 빠르게 압축하는 현재 방식은 “최대 배속”을 두거나, 짧은 효과와 긴 효과용 클립을 구분하는 방향으로 수정한다. 권장 1차 기준은 일반 피격 최대 1.5배, 중량·폭발 최대 1.25배다.

## 6. 크기·색상·레이어 기준

- 일반 피격은 보통 적 몸체 폭의 0.6~1.0배에서 시작한다.
- 중량 타격은 1.0~1.4배, 범위 폭발은 실제 피해 반경을 넘지 않도록 한다.
- 작은 적과 보스에 같은 고정 크기를 강제하지 않고 Collider 또는 Renderer bounds를 기준으로 2~3단계 크기를 선택한다.
- Hacker 주색은 청록·전기 파랑, 보조색은 물 계열 밝은 청색과 제한적인 자홍색으로 잡는다.
- Cyborg 주색은 적색·주황, 전기/플라즈마 계열은 흰색 중심광과 청색 또는 적색 외곽광으로 구분한다.
- 속성 확인에 필요한 색만 사용하고 캐릭터·적 실루엣을 완전히 가리는 흰색 면적은 줄인다.
- 지면/잔류 효과, 캐릭터, 피격 섬광, UI 순으로 Sorting Layer를 분리한다. 검은 사각형은 투명 머티리얼·알파 임포트·셰이더 조합을 먼저 확인한다.

## 9. 뱀서라이크 레퍼런스에서 가져올 원칙

- Vampire Survivors 계열은 다수의 자동 공격과 적이 한 화면에 겹치므로, 개별 효과의 정밀함보다 공격 범위·방향·속성의 즉시 판독이 중요하다.
- HoloCure는 Vampire Survivors와 Magic Survival에서 영감을 받은 픽셀 기반 다수 적 전투 게임이다. NeoSurvive에는 픽셀 팔레트 통일, 캐릭터별 색 구분, 짧고 반복 가능한 효과라는 관점을 적용한다.
- Brotato는 최대 6개 무기를 동시에 사용하는 자동 발사형 아레나 슈터다. 여러 무기가 겹칠 때 발사체/피격 효과의 크기와 수를 제한하고 적 실루엣을 보존하는 기준에 참고한다.
- 위 항목 중 구체적인 시간·크기 수치는 NeoSurvive의 현재 공격 주기와 96×96 hun0fx 원본을 기준으로 정한 내부 제안이며, 타 게임의 수치를 그대로 복제한 것이 아니다.

## 10. 성능과 구현 원칙

- 데미지 판정과 VFX 재생을 분리한다. VFX가 생략돼도 피해는 정상 적용되어야 한다.
- 지속 피해는 매 `FixedUpdate` 또는 매 데미지 틱마다 Instantiate하지 않는다.
- 동시 생성량이 많은 Link Pistol, Drone, Turret, Chain Saw, Breath부터 풀링 대상으로 잡는다.
- 1차 목표는 화면 내 피격 이펙트 30~50개에서도 프레임 드랍과 GC 스파이크가 눈에 띄지 않는 것이다. 실제 상한은 프로파일링 후 확정한다.
- SpriteRenderer tint·sorting·scale·lifetime은 프리팹/Inspector에서 직접 조정 가능하게 유지한다.
- 무기별 별도 매니저를 만들지 않고 현재 `WeaponHitVfx` 연결점을 확장한다. 추적, 크기 단계, 배속 상한처럼 공통으로 필요한 항목만 추가한다.

## 11. 작업 순서

1. 현재 미완료 병합의 누락 GUID와 `.meta`를 복구한다.
2. 기존 11개 피격 연결을 Play Mode에서 다시 확인한다.
3. `WeaponHitVfx`에 배속 상한과 선택적 짧은 목표 추적 방식을 추가한다.
4. EMP, Chain Saw, Breath 세 종류로 단발/지속/범위 기준을 먼저 검증한다.
5. 나머지 기존 피격 이펙트에 같은 기준을 적용한다.
6. 발사·이동·종료 이펙트는 무기별로 한 개씩 추가하고 QA한다.
7. 고밀도 전투에서 풀링과 동시 생성 제한을 적용한다.
8. 스크린샷·짧은 영상과 Inspector 수치를 문서에 갱신한다.

## 14. 기존 연출과 신규 연출의 경계

현재 문제는 이펙트의 방향 자체보다 “기존 연출에서 무엇을 보존하고 무엇만 개선했는지”가 명확하지 않은 점이다. 앞으로는 아래 네 항목을 먼저 기록한 뒤 작업한다.

| 구분 | 반드시 기록할 내용 | 판단 기준 |
| --- | --- | --- |
| 기존 기준선 | 기존 발사체, 궤적, 피격, 폭발, 공격 주기 | 신규 이펙트를 모두 끈 상태의 영상 또는 스크린샷 |
| 변경 목적 | 타격 위치, 속성, 강도 중 무엇을 더 잘 보이게 할지 | 한 무기당 핵심 목적 1개 |
| 허용 범위 | 바꿔도 되는 프리팹·클립·Inspector 값 | 데미지·판정·사거리·공격 주기는 별도 승인 없이 변경 금지 |
| 변경 결과 | 변경 전후 수치와 화면 차이 | 같은 적, 같은 무기 레벨, 같은 카메라에서 비교 |

신규 연출은 기존 무기 연출을 교체하는 것이 아니라 부족한 정보 한 가지를 보완해야 한다. 기존 발사체가 이미 방향을 보여주면 추가 궤적을 겹치지 않고, 기존 폭발이 범위를 충분히 보여주면 피격 이펙트는 작게 유지한다.

## 15. 일관적인 레퍼런스 체계

레퍼런스는 게임별 외형을 그대로 섞지 않고 아래 순서로 사용한다.

1. **NeoSurvive 기존 무기**: 픽셀 크기, 카메라 거리, Sorting Layer, 캐릭터 주색의 기준이다.
2. **hun0fx 원본**: 프레임, 실루엣, 팔레트를 훼손하지 않는 애니메이션 원본이다.
3. **HoloCure 계열**: 픽셀 화면에서 캐릭터와 공격 속성을 구분하는 기준으로만 참고한다.
4. **Brotato 계열**: 여러 무기가 동시에 출력될 때 효과 수와 크기를 제한하는 기준으로만 참고한다.
5. **Vampire Survivors 계열**: 자동 공격에서 범위와 공격 주기를 즉시 읽게 하는 기준으로만 참고한다.

각 레퍼런스에서 가져오는 것은 `역할`이지 `모양 전체`가 아니다. 한 무기는 한 개의 주 레퍼런스만 선택하고, 보조 레퍼런스는 색 또는 시간 중 한 항목에만 사용한다.

### 캐릭터별 공통 문법

| 항목 | Hacker | Cyborg |
| --- | --- | --- |
| 기본 실루엣 | 얇은 선, 원형 파동, 디지털 파편 | 두꺼운 절단선, 충격파, 기계 스파크 |
| 주색 | 청록·전기 파랑 | 적색·주황 |
| 강조색 | 흰색 중심광, 제한적 자홍 | 흰색 중심광, 제한적 청백색 |
| 움직임 | 빠른 점멸 후 짧은 잔광 | 강한 첫 프레임 후 감쇠 |
| 피격 인상 | 교란·전기·데이터 | 절단·중량·열·금속 |

## 16. 과한 이펙트를 줄이는 통합 규칙

### 한 타격에는 대표 피격 이펙트 하나만 사용한다

- 같은 피해 판정에 여러 hun0fx 피격 애니메이션을 동시에 겹치지 않는다.
- 발사·궤적·피격·폭발은 역할이 다를 때만 함께 사용한다.
- 일반 적에게는 대표 피격 1개, 보스 또는 마스터 공격에만 보조 잔광 1개를 허용한다.
- 색상 변경, 화면 흔들림, 피격 플래시가 이미 강하면 피격 스프라이트의 밝기와 크기를 낮춘다.

### 루프와 생성 간격

- 단발 피격 애니메이션은 루프하지 않고 한 번 재생 후 제거한다.
- 지속 공격은 데미지 틱마다 새 피격 애니메이션을 만들지 않는다.
- 체인소·브레스·지속 빔은 목표별 0.25~0.45초 간격을 기본으로 한다.
- 지속 이펙트를 사용할 경우 “하나를 유지하고 갱신”하며, 같은 목표 위에 중첩하지 않는다.
- 화면에 같은 종류의 피격 이펙트가 과도하게 쌓이면 가까운 시간대의 작은 타격을 생략한다. 피해 판정은 생략하지 않는다.

### 원본 훼손 방지

- `Hun0fxOriginal`의 PNG, JSON, 프레임 수, 원본 해상도는 수정하지 않는다.
- 원본을 확대 저장하거나 보간된 이미지를 새 원본처럼 덮어쓰지 않는다.
- 크기 조정은 Runtime 프리팹의 Transform 또는 `WeaponHitVfx.scale`에서만 수행한다.
- 기본 확대는 원본 프리팹 기준 0.75~1.25배 안에서 시작한다.
- 1.5배를 넘는 확대는 중량 공격·보스 공격·범위 폭발에만 사용하고 변경 사유를 기록한다.
- Pixel Perfect 기준과 PPU를 유지하며 Bilinear 필터나 손실 압축을 사용하지 않는다.

### 화면 밀도 예산

한 공격에서 동시에 강조하는 요소는 최대 두 개로 제한한다.

- 일반 공격: `궤적 + 피격` 또는 `발사 + 피격`
- 범위 공격: `범위 예고 + 폭발`
- 지속 공격: `지속 본체 + 간헐적 피격`
- 중량 공격: `공격 궤적 + 큰 피격`

발사, 궤적, 피격, 폭발, 잔류, 화면 흔들림을 모두 최대로 사용하지 않는다.
